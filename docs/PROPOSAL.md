# Proposal (ร่าง) — Slip Ledger

**โจทย์และผู้ใช้:** นักศึกษาและคนทำงานจำนวนมากจ่ายเงินผ่านการโอนและสแกน QR แทบทุกวัน
แต่ไม่ได้จดบัญชี เพราะการพิมพ์รายการเองจากสลิปทีละใบน่าเบื่อ Slip Ledger ให้ผู้ใช้อัปโหลด
รูปสลิปโอนเงินหรือใบเสร็จ แล้วแอปจะอ่านวันที่ ยอดเงิน ผู้รับ/ผู้จ่าย เลขอ้างอิง และหมวด
ออกมาเป็นรายการบัญชีที่ผ่านการตรวจ schema ให้ผู้ใช้ยืนยันก่อนบันทึก จากนั้นผู้ใช้ถามเป็น
ภาษาไทยได้ เช่น "เดือนนี้ใช้ค่ากินไปเท่าไหร่" โดย agent จะเขียน SQL แบบอ่านอย่างเดียวไปค้น
บัญชีแล้วตอบพร้อมตัวเลข

**เทคนิคจากวิชาที่ใช้:** (1) structured output แบบ multimodal + ตรวจ schema ด้วย Pydantic
และ parse-then-repair, (2) agent loop ที่มี tool SQL แบบ allow-list + เงื่อนไขหยุด,
(3) evaluation บนชุดทดสอบที่ติดเฉลยเทียบกับ baseline, (4) FastAPI + web UI

**การวัดผล:** (ก) การอ่านสลิป — ชุดสลิปจริงที่ปิดข้อมูลส่วนตัวแล้วประมาณ 30 ใบจากหลาย
ธนาคาร ติดเฉลยเอง วัดความแม่นยำรายช่อง (วันที่ ยอดเงิน ทิศทาง ผู้รับ) เทียบ prompt แบบ
ทั่วไปกับ prompt ที่ออกแบบสำหรับสลิปไทย (ข) การตอบคำถาม — 20 คำถามบนบัญชีจำลอง 3 เดือน
คำนวณเฉลยจาก SQL วัด accuracy เทียบ baseline ที่ยัดทั้งตารางลงใน prompt โดยไม่มี tool
(ผลรอบแรก: baseline 15%, agent 70%)

**ขอยืนยันกับอาจารย์:** โปรเจกต์นี้ไม่ได้เน้น RAG — "corpus" คือชุดรูปสลิป และ "การปรับปรุง
ที่วัดผลได้" คือการเปรียบเทียบ prompt / การ normalize ข้อมูล แทนการปรับ `min_score`
ตีความแบบนี้ได้หรือไม่
